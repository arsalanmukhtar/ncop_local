NWFC Station Observations — Weather Types Reference
=====================================================

Endpoint:  /api/pmd/nwfc/observations/  (per GCOP_PMD_API_Integration.md §4.1)
Property:  weather   (top-level string on each feature's properties)

Every string the NWFC scrape has been observed to emit for the `weather`
property is listed below, grouped by the animated icon it maps to on the
NCOP map.  The keyword patterns (regex, case-insensitive) in the right
column are exactly what nwfcWeatherIconId() matches against, so any new
string containing one of those keywords will automatically land in the
correct icon bucket without a code change.

Notes
─────
1. Weather strings are matched case-insensitively and via SUBSTRING —
   e.g. "Rain-Thundershower" matches `thunder` first (thunderstorm
   bucket) because the pattern list is evaluated top-to-bottom.
2. Precedence order (top wins if a string could match multiple):
     thunder / lightning  →  drizzle  →  shower / rain
     snow / blizzard / sleet / hail  →  fog / mist / haze
     dust / sandstorm  →  partly cloud  →  overcast  →  cloud
     gust / wind  →  hot / scorch  →  cold / freez / chill  →  clear
3. Empty / null / unrecognised strings fall through to the DEFAULT
   thermometer icon rather than showing nothing.
4. Every icon is drawn frame-by-frame in map-icons.js — no external
   image resources, no CORS, no CSP concerns.  See NWFC_DRAWERS.

Source of truth
───────────────
- nwfcWeatherIconId(text)          → frontend/src/modules/map-icons.js
- nwfcWeatherEmoji(text)  (popup)  → frontend/src/modules/layer-attribute-popup.js
- NWFC_DRAWERS  (canvas drawers)   → frontend/src/modules/map-icons.js
